# 新日记模板编辑 PRD

状态：已实现 · 2026-10-26

## 背景

新建日记时，Glimmer 会复制一篇专门的模板日记（`TEMPLATE_DIARY_ID`）的标题和正文。2026-10-02 为了减少界面上的常驻按钮，桌面侧栏、日记列表顶部、手机顶栏三处「日记模板」按钮都拿掉了。模板本身仍在生效，但界面上已经改不了：想调整每天的固定结构（比如加一节「今日感受」），只能改代码。

模板一年可能只改几次，但改不了的时候就完全没办法。所以它需要一个入口，只是不该占日常写作的视线。

## 目标

- 想改模板的人，在「设置」里能找到入口，不需要记住任何手势。
- 进入模板后清楚地知道自己在改模板，改完一键回到原来那篇日记。
- 日常写作界面（侧栏、列表、编辑器顶部）不新增任何常驻元素。

## 非目标

- 多套模板、按文件夹或星期切换模板。
- 模板变量（除了标题前面的日期，正文里不做 `{{date}}` 这类替换）。
- 恢复 10-02 之前那个带预览、保存按钮的模板弹窗：模板本身就是一篇日记，编辑器已经能所见即所得地改它，弹窗是重复的一套编辑界面。

## 入口放哪

| 方案 | 结论 | 理由 |
| --- | --- | --- |
| 设置 → 常规里加一行「新日记模板」 | 采用，作为唯一入口 | 低频配置大家本来就去设置里找；桌面和手机都有设置按钮，一处改动两端都有。 |
| 右键或长按「新建日记」按钮出菜单 | 不做 | 手机上没有右键，长按没人会去试；入口和需要它的时刻贴得近，但找不到等于没有。 |
| 新建日记后在编辑器里提示「改模板」 | 不做 | 每次新建都打扰写作，为一年几次的操作付出每天的注意力。 |
| 恢复侧栏或列表顶部的按钮 | 不做 | 正是 10-02 要去掉的常驻元素。 |

## 方案

只有入口不够。模板日记不出现在日记列表里，现在打开它只有标题上方一个「模板」小标签：改完之后用户不知道改动有没有保存、对谁生效、怎么回去。所以方案分两部分：入口，以及进入后的提示条。

### 1. 设置里的入口

设置 → 常规，在「数据管理」和「云同步」之间加一节：

- 标题：新日记模板
- 说明：每次新建日记都会复制这份模板的标题和正文。改动只影响之后新建的日记；登录云同步时，其他设备也会用这份模板。
- 一行操作（和「导入」「导出」同样的行样式）：「编辑模板」，副文案「在编辑器里打开模板」。

点击后：关闭设置弹窗，在编辑器里打开模板日记；手机上同时切到编辑器视图；记下打开前正在看的那篇日记。

### 2. 编辑模板时的提示条

模板日记打开时，编辑器顶部（标题区上方，替换现在的「模板」小标签）显示一条浅蓝提示条，沿用现有 `glimmer-info-strip` 的样式：

- 文字：正在编辑新日记模板。改动自动保存，从下一篇新日记开始生效。
- 右侧主按钮「完成」：回到打开模板前的那篇日记；那篇已经不在了（被删或移进废纸篓），就回到列表里最新的一篇。
- 右侧次按钮「恢复默认」：弹确认框「把模板恢复成默认的『流水账 + 今日计划』？当前模板的改动会丢失，已经写好的日记不受影响。」，确认后把标题清空、正文换成 `DEFAULT_TEMPLATE_DIARY_CONTENT`。

标题输入框留空时的占位文字「留空则只用日期」保留现状。

## 不变的行为

- 已经写好的日记不受模板改动影响。
- 模板日记不出现在日记列表、搜索、日历、导出、回收站里，也不能被移进文件夹或删除；打开模板时不显示「导出」按钮。
- 模板日记和普通日记一样同步到云端（改动走同一条同步队列），所以登录同一账号的设备共用一份模板。
- 「把未完成事项挪过来」不会把模板当成来源或目标。
- 新建日记的标题仍是「日期」或「日期 - 模板标题」。

## 验收

1. 桌面和手机都能从 设置 → 常规 → 编辑模板 打开模板，设置弹窗随之关闭。
2. 打开模板后顶部有提示条；在模板里加一节标题，点「完成」回到原来那篇日记。
3. 再新建一篇日记，正文里有刚加的那一节；之前的日记内容没变。
4. 刷新页面后模板改动仍在（桌面版重启后仍在）。
5. 「恢复默认」取消时什么都不变；确认后模板回到默认内容，之后新建的日记用默认内容。
6. 打开模板前看的那篇日记被删掉后，点「完成」落在列表最新一篇，不出现空白编辑器。
7. 模板里的空待办不会被「把未完成事项挪过来」带进新日记。
8. 日常界面（侧栏、列表顶部、手机顶栏）没有新增按钮。
