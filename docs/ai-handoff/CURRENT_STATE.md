# CURRENT_STATE

它只回答一个问题：**Glimmer 现在已经做到哪一步，哪些能力已存在，哪些区域接手前要先复核。**

## 当前项目快照
Glimmer 现在已经不是早期 demo，而是一个本地优先、可选接入 Supabase 云同步的个人写作产品。桌面端主数据会在启动时迁移到 Tauri App data 目录下的文件 KV 存储，Web 端继续使用 `localStorage` 兼容路径。主界面围绕“左侧组织与视图切换 + 中间日记正文编辑 + 若干增强面板/弹窗”组织。当前核心状态是：写作、文件夹组织、正文待办、导出、模板、可选账号都已接入同一个产品里。AI 只走本机 Claude Code，产品不保存任何模型 API key。

## 已稳定存在的能力
### 富文本与正文编辑
- 使用 TipTap 作为编辑核心，支持标题、列表、任务列表、引用、图片、链接、分隔线等常见正文能力。
- 表格已不能新建：工具栏按钮和表格气泡菜单都下线了，`Editor.tsx` 里只保留 `Table` / `TableRow` / `TableCell` / `TableHeader` 四个基础节点。这条限制是有意的——去掉任何一项，TipTap 解析旧正文时会把已经写好的 `<table>` 静默丢掉。旧表格能读能改，只是不能再加新的。
- 列表支持真实层级缩进，不再只是插空格。

### 组织与回看
- 新建日记自动放进当月文件夹（名字形如 `2026-09`），不看当时左侧选中的是哪个，并把左侧切到那个文件夹。当月文件夹不存在就新建一个，放在最近那个月份文件夹的同一层。一个月份文件夹都没有时不接管，照旧放进选中的文件夹（`src/utils/monthFolder.ts`）。
- 左侧保留文件夹与任务入口；标签和日历入口已下线，避免把写作产品变成维护型归档系统。

### 待办
- 待办只存在于日记正文的勾选框里，没有独立的任务实体和任务面板。他的实际用法是在正文里管待办、日程放 Mac 日历。
- 勾选框有三种状态：空、打勾、打叉，连续点同一个框循环「未勾 → 打勾 → 打叉 → 未勾」。打叉在存储上仍是已完成，只多一个 `markState`（HTML 里 `data-state="dropped"`），所以跨日挪移、长期在做、父项打勾都按已完成处理；打叉不改子项，子项没做完会照常被提议挪走。编辑器里的勾选框因此改成自绘按钮（`src/components/Editor/taskItemMark.ts`），系统 checkbox 画不出叉。
- 新建日记旁边有「补写」入口：选过去的一天，按那天的日期生成标题、归到当月文件夹，只保留流水账（不插今日计划）。这一天已经有日记时直接打开已有的，不再新建第二篇。正常点「新建日记」仍然是今天。
- 打开最新的那篇日记时，若更早的日记里有没勾完的事项，编辑器上方那条横条会问要不要「挪到这篇」。翻回旧日记不提示，免得事项被挪进旧日记藏起来。接受后目标日记插入一份未勾选的副本，只带没做完的子项。源日记里：下面没有做完子项的事项整条删掉；下面有做完子项的，留下它的文字但去掉勾选框、变成普通列表项，下面只挂做完的那些，更深的层级同样一层层处理（`leaveDonePartsBehind`、`splitMixedLists`）。这样那天的记录保留做了什么，每件没做完的事只在一个地方是待办。
- 挪完原处出现撤销条，关掉或刷新前都能撤销。撤销把挪来的条目带着现在的样子（改过的字、勾选、子项）送回原日记；条目和原日记都没动过时原样换回原日记，否则补进原日记的「今日计划」。挪完后被删掉的条目不补回，这篇里新写的其他内容不受影响。
- 结转认条目靠正文文本归一化（`normalizeTaskText`）加出现顺序：同一篇里同名的事项记成「跑步#1」「跑步#2」，各挪各的。目标日记里已经有字面相同的一条，就不再提议挪。先后按标题日期排（`diaryDay`），同一天再看创建时间。
- 挪入目标日记的条目会写上标记（`data-task-id`，值以 `carry-` 开头），撤销时按标记取回条目现在的版本送回原日记。
- 编辑器 schema（`CustomTaskItem`）必须保留 `taskId` 属性，否则 TipTap 解析时会把 `data-task-id` 从正文里抹掉，撤销就认不回条目。

### 导出与模板
- 粘贴 Markdown 原文会转成标题、列表等格式；从代码编辑器或聊天窗口的代码块复制时剪贴板里附带的那份只是包了一层的 HTML，同样按 Markdown 转换（`isPlainTextHtml`）。来源里已经有标题、列表这类排版时按原样粘贴。
- Markdown 导出逐个元素转换（`htmlToMarkdown`），保留勾选状态（`- [x]`）、嵌套层级、链接地址和图片。Word 导出按标题、段落、列表项分段（`htmlToDocBlocks`）。HTML 和 PDF 导出前会清掉正文里的脚本、事件属性和 `javascript:` 链接（`sanitizeDiaryHtml`），标题做转义。
- 桌面版窗口不处理网页下载，所有导出（导出窗口、完整数据、备份下载）在桌面版都由 `save_to_downloads` 写进「下载」文件夹并在访达里选中，网页版照旧走浏览器下载（`src/utils/fileSave.ts`）。
- 导入日记统一走 `storage.importDiaries`：合并模式下同一篇只在导入版本更新时替换；替换模式下本机原有、导入里没有的日记排队从云端删除。改动过的日记记为待上传，由下一次和云端合并时补传。
- 导入：Word 用 mammoth、PDF 用 pdf.js，都在用到时按写死的路径加载；解析不了算这份文件导入失败，不生成占位日记。桌面自动备份（数据包在 `data` 里一层）可以直接导入。
- 导出已支持 Markdown、HTML、JSON、DOCX、PDF。
- 导出不仅支持“当前日记”，也支持“全部日记”，并能选择合并单文件或拆分多文件。
- 新建日记复制一篇专门的模板日记（`TEMPLATE_DIARY_ID`）的当前内容。编辑入口只有一处：设置 → 常规 → 编辑模板，在编辑器里打开这篇系统日记；打开时顶部有提示条，「完成」回到打开前那篇（那篇不在了就回最新一篇），「恢复默认」换回 `DEFAULT_TEMPLATE_DIARY_CONTENT`。模板日记和普通日记一样走云同步。详见 `docs/TEMPLATE_EDITING_PRD.md`。

### 同步与认证
- 桌面版退出：后端在关窗口或 Cmd+Q 时先拦下退出，发 `glimmer://flush-before-exit` 让前端把数据文件写完，前端调 `finish_exit` 再退出，两秒没回应也会退。更新重启前也先写盘。
- 桌面数据文件读不出来时，原文件另存为 `glimmer-store.unreadable-<时间>.json`，这次从空白开始，顶部提示副本和自动备份的位置。
- 本机存储读写哪个账号的数据只由 `AuthContext` 决定，在渲染时设好：有会话用会话账号，会话过期或连不上云端用上次登录的账号，都没有才用「未登录」那块。别的模块不要再调 `setCurrentUserId`。切到某个账号时，「未登录」那块里他写的日记、文件夹、废纸篓会并进账号（`storage.adoptAnonymousDiaries`），新并入的日记记为待上传。
- 账号操作在「设置 → 账号」：看当前账号、退出登录，没登录时给登录入口。左下角的同步按钮只管同步。
- 同步状态面板只显示当前状态、待同步数量和「上次同步成功」的时间（`src/utils/lastSync.ts`，每次同步成功时更新），没有同步历史列表。
- 拉取云端后的合并规则在 `planCloudMerge`（`src/utils/diaryMerge.ts`）：按请求返回时的本地数据合并；废纸篓里和删除还在排队的日记不会被拉回，云端残留补删；本机比云端新的、没登录时新建的补传。请求返回时账号已经换了就丢弃结果。另一台设备删掉的日记这边认不出来，因为云端没有删除记录。
- 文件夹同步（`useFolders.ts`）：每次新建、改名、删除都先排进队列再立刻发一次，没登录或登录过期时也排（记在上次登录的账号下）。拉取文件夹时，排着队的删除和改名以本机为准，其余以云端为准；切回窗口时最多每分钟拉一次。删文件夹时，里面日记移出文件夹、修改时间记成现在并记为待上传。
- 同步队列：失败的操作一直保留到成功为止，同一条记录只保留最后一个操作；重试日记时用本机最新版本，云端已有更新版本就跳过。
- 云端连不上后停用 30 秒，之后自动重试（`src/utils/supabase.ts`）。
- 恢复备份和整份导入会把日记修改时间改成当前，保证重新加载后不被云端旧版本盖掉；桌面版刷新前等数据文件写完。
- 桌面版登录页有「记住密码」「自动登录」两个勾选框（默认都勾，自动登录依赖记住密码）。登录成功时把邮箱、按选择决定是否存的密码和自动登录开关存进系统钥匙串（`src-tauri/src/credentials.rs`）。勾了自动登录，登录状态续不上时自动用存下的密码重新登录，期间不显示「登录已过期」；失败后十分钟内不再重试。登录页按上次的选择预填。主动退出登录不会被自动登回去，但钥匙串里的记录保留。网页版不显示这两个勾选框，交给浏览器自己的记住密码。
- 本地优先仍然成立；即使 Supabase 不可用，本地仍应工作。
- 账号系统基于 Supabase Auth，当前方向是内部账号优先，而不是公开注册产品。桌面端会把 Supabase 登录态复制到文件 KV，启动时再补回 SDK 需要的 `localStorage` key，避免 WebKit 容器变化导致反复掉登录。

## 特殊机制与系统实体
- `LONG_TERM_MASTER_ID`：长期想法主日记，是系统实体，不是普通用户日记。
- `TEMPLATE_DIARY_ID`：模板日记，新建日记时复制它的当前内容和标题规则。
- `Diary.content`：正文真相源。富文本、表格、任务列表样式都围绕这份 HTML 内容保存和导出。
- 本地存储使用当前用户 ID 做 key 前缀；登录态切换会影响读取哪一组本地数据。桌面端主数据不应继续依赖浏览器 `localStorage` 容量，登录态则需要同时兼容 Supabase SDK 的 `localStorage` 读取方式。
