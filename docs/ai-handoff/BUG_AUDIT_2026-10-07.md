## 一、会丢数据、数据回退或数据看不见

| # | 问题 | 位置 | 状态 |
|---|---|---|---|
| D1 | 登录状态过期（尤其离线启动）时，存储作用域被设成空，界面读写的是「未登录」那块数据，账号里的日记看不见，新写的也写错地方；当天的本地备份还会备份这块空数据 | `useDiaries.ts` 设置 `setCurrentUserId(userId)`、`AuthContext.tsx` init 里 `setCurrentUserId(null)`、`useFolders.ts` | 已修：存储作用域只由 AuthContext 在渲染时决定（会话账号，没有就用上次登录的账号）；浏览器模拟登录过期后作用域为账号、日记正常显示 |
| D2 | 没登录时写的日记，合并进账号后不会补传：待补传名单和废纸篓没有一起搬过去 | `storage.ts` `copyAnonymousDataToUserIfEmpty` | 已修：切到账号作用域时把「未登录」那块里写的日记、文件夹、废纸篓并进账号，新并入的日记记为待上传；浏览器实测 |
| D3 | 没登录时删掉并在废纸篓里永久删除的日记，重新登录后被云端拉回来 | `useDiaries.ts` deleteDiary / purgeDiary，`diaryMerge.ts` | 已修：登录过期时删除也排进队列（记在上次登录的账号下），排着的删除挡住云端拉回；浏览器实测入队 |
| D4 | 没登录时从废纸篓恢复的日记，不改正文就永远不上传 | `useDiaries.ts` restoreDiary | 已修：登录过期时恢复排进队列上传，并顶掉排着的删除；浏览器实测 |
| D5 | 「合并」导入不比较修改时间，旧备份会盖掉这周改过的日记 | `useDiaries.ts` importDiaries，`storage.ts` importAllData | 已修：导入统一走 storage.importDiaries，合并时只在导入版本更新时替换；实测 |
| D6 | 导入完整数据 JSON 只写本机：备份里有、云端没有的永远传不上去；「替换」模式下被替换掉的日记下次同步又被拉回 | `ImportModal.tsx`，`storage.importAllData` | 已修：导入改动的日记记为待上传，替换模式下多出来的排队从云端删除，导入后马上和云端合并一次；实测 |
| D7 | 同步队列只在浏览器发出「重新联网」或手动点重试时才跑，服务器出错后排队的删除和文件夹改动一直不发 | `syncManager.ts` | 已修：登录后立刻发一次队列，之后每分钟重试 |
| D8 | 文件夹同步没有日记那套保护：删掉的文件夹会回来、改名会被旧名盖回、没登录时建的文件夹不上传、删文件夹后其中日记的归属又被云端拉回 | `useFolders.ts`，`syncManager.ts` 文件夹分支，`storage.deleteFolder` | 已修：文件夹改动一律先进队列再发；重试用本机当前版本；拉取时排着的删除和改名以本机为准，切回窗口时也拉；删文件夹时里面日记的修改时间记成现在并待上传；实测 |
| D9 | 桌面版数据文件改动后 120 毫秒才写，Cmd+Q、关窗口、更新重启前没有先写完 | `desktopStore.ts`，`DesktopUpdateNotice.tsx` | 已修：关窗口和 Cmd+Q 时后端先拦下退出、通知前端写盘，写完再退（两秒兜底）；更新重启前也先写盘。只验了编译，没在打包版里实测 |
| D10 | 桌面数据文件损坏时静默改用浏览器存储，打开几乎是空的，没有任何提示 | `desktopStore.ts` hydrate | 已修：读不出来时另存副本、从空白开始继续用桌面存储，并在顶部显示提示说明副本和备份在哪。只验了编译 |
