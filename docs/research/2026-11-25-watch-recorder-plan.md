# 全天录音 + 身体数据 → 日记和规律：自建方案

2026-11-25。前情和别人的做法见同目录 `2026-11-25-watch-all-day-recording.md`。本文是方案，未动手写代码；标「待实测」的要真机验证。Claude 出初稿，Gemini 独立出一份，已合并，对照见文末。

## 要做成什么

1. 每天晚上或第二天早上，自动出一份当天按一件件事整理的记录，带每件事时的身体状态。记录放在私人项目里，不进 Glimmer 日记列表，他写日记时参考。
2. 攒够几周数据后，agent 能指出他自己没注意到的规律，比如「开会多的第二天夜里 HRV 偏低」，并能翻出是哪几天、哪几件事。

## 整体数据流

```
手表：一直录音，每 30 分钟存一个文件 ──蓝牙/Wi-Fi──▶ iPhone
iPhone：收音频；每天导出前一天的 Health 数据 ──iCloud Drive 文件夹──▶ Mac
Mac：拼接当天音频 → FluentFlow Local 转写（带绝对时间）→ 切成事件
     → 写事件表、日表（本机 SQLite）→ 生成日记 → Glimmer 收件箱 → Glimmer 桌面版
     每周：跨天比较日表，出「候选规律」报告
```

各环节放在哪、为什么：

- **手表只录音、不做别的**。心率事后从 Health 读，不开体能训练会话（省电）。不开会话时能不能熄屏一直录，待实测；不行再退回开会话的做法。手表上留两个按钮：「暂停 30 分钟」（进敏感场合前点）和「删掉刚才 15 分钟」（直接在手表上删，不传不转写）。
- **转写放 Mac**，用 FluentFlow Local 的 faster-whisper：中文比 iPhone 自带识别准，而且整天的音频拼起来转，切块处不会把一句话切断。
- **iPhone 到 Mac 用 iCloud Drive 里的一个文件夹**，不搭服务器。一天 16 小时音频按单声道 16kHz、32kbps 压缩约 230MB，Mac 取走转写后从 iCloud 删掉，占用的 iCloud 空间不会累积。
- **事件表、日表存在 Mac 本机的 SQLite 文件里**，放在新私人项目的 `private/` 下，不进任何仓库。agent 写记录和找规律都直接查这份。
- **一天从凌晨 4 点算起**：凌晨 1 点熬夜聊的事算前一天；夜里的睡眠算在醒来那天。

## 切块和切事件是两回事

- **文件块（30 分钟）**：只为可靠和省电。App 崩了最多丢半小时；无线传输不用那么频繁。文件名写绝对开始时间，Mac 按时间拼回整天。
- **事件（记录里的一段）**：整天转写出来后再切，不按钟点。候选分界有四种：超过 10 分钟左右没人说话、Mac 日历里日程的开始结束、运动开始结束、走路和久坐之间切换。再交给模型按话题合并或拆开，给每件事起标题、写摘要、标人物和标签。长时间没人说话的时段合成一条「安静时段」，不拆成碎片。他抽查一天的切分对不对，规则按他的反馈改。

## 两张表

另有一张原始心率表（每个心率采样一行：时间、数值、来源是手表还是 AirPods），事件和日表的心率都从这里算。

**事件表**：一天里每件事一行。

| 字段 | 说明 |
|---|---|
| 开始、结束时间 | |
| 标题、摘要 | 模型写 |
| 人物 | 对话里出现的人（称呼即可） |
| 标签 | 模型从固定词表里选，词表他可增删：开会、上课、和人聊天、独自工作、通勤、运动、吃饭、争执、被表扬… |
| 说话时长 | 这段里有人说话的总分钟数 |
| 心率：平均、最高、和当天静息心率的差 | 跨天比较用「差」，不用绝对值 |
| 心率采样数、来源（手表/AirPods） | 平时手表几分钟才记一次，样本太少的事件不参与心率比较 |
| 每分钟步数 | 用来排除「心率高只是因为在走路」：只有步数很少时心率偏高，才算可能和情绪有关 |
| 转写、音频位置 | 指向文件，表里不存全文 |

**日表**：每天一行。

| 字段 | 说明 |
|---|---|
| 当晚睡眠：入睡和起床时间、总时长、深睡和快速眼动时长 | Health 睡眠数据 |
| 夜间 HRV、静息心率 | 夜里测的最稳定，适合跨天比。白天 HRV 太稀疏，不算到每件事上，也不像开源版那样换算「压力值」 |
| 佩戴和录音覆盖率 | 白天有心率数据的时段占比、录到的小时数。太低的日子标为低可信，不参与比较 |
| 工作日或休息日 | 比较时分开比，免得把「工作日的特点」当成「开会的影响」 |
| 步数、运动 | |
| 当天各类标签的次数或分钟数 | 从事件表汇总：开会 3 次、聊天 90 分钟… |
| 自评（可选） | 睡前在手表上点一下 1–5 分的状态。规律需要一个「结果」，身体指标之外有他自己的感受会更有用 |
| 补记标签 | 他或 agent 补的事件表抓不到的事：喝咖啡、喝酒、生病、熬夜 |

## 找规律怎么做

- **比法**：拿日表里一个因素（比如「开会 ≥3 次」）把天分成两组，比结果指标（当晚 HRV、第二天静息心率、睡眠、自评），同一天和第二天都看，因为很多影响是延后的。脚本只负责算差多少、各组有几天；哪些值得比、结果说明了什么由模型提假设、他判断。
- **防假规律**：每组少于约 8 天不报；工作日和休息日分开比；去掉最极端的一天后结论反过来的不报；同一时期还有别的变化（考试周、生病、喝酒）时写出来；一次比很多个因素总会有几个碰巧显著，所以每次报告最多给一两条，只当「候选」，再观察两三周仍成立才算。前两周只建立他的个人基线，不下任何结论。
- **回头解释**：每条候选规律附上对应的几天和几件事，可以点回事件表和原话。
- **频率**：攒满 4 周后开始，每周出一次报告，进 Glimmer 作为一篇。

## 日记和 Glimmer

和已定方向的冲突：Glimmer 2026-10-28 定过「日记由人来写；之前让 agent 每天自动写日记，用下来不如自己写，agent 写的内容不再进日记列表；要放开新的一类，一项一项加，每加一项先问使用者」（`docs/ai-handoff/PRODUCT_BRIEF.md`「产品分工」）。两条路（2026-11-25 定走 A）：

- **A. 不进 Glimmer 日记列表**：每天的整理记录放在私人项目里，他自己写日记时参考。agent 额外读他手写的日记，和当天的身体数据对照（比如「你写下午很平静，但那段对话时心率是全天最高」）。Glimmer 不用改。
- **B. 放开一类「当天回放」**：Glimmer 的 agent 收件箱加一种「新建一篇」的单子（现在只能改「长期任务」一篇），回放放进单独的文件夹、标题和手写日记区分，同一天不重复建，绝不改他手写的正文。这部分是通用功能，可以进公开的 Glimmer 仓库。

无论哪条，录音、转写、两张表、手表 App 都放另一个私人项目。

## 隐私

- 会录到别人。音频只存在他自己的设备上，不进任何云服务（iCloud 只做中转，Mac 取走就删）；转写完保留几天供抽查，之后删音频、只留文字。
- 以后可加：在 Mac 本机区分他本人和别人的声音，别人的话只留概括、不留原话。本机能不能分得准待实测，不放进第一版。
- 写日记和找规律要把转写交给模型。用哪家模型（会把别人的话发出去）是他的选择，见文末。

## 分阶段

| 阶段 | 做什么 | 怎么算过 |
|---|---|---|
| 0. 看已有数据 | 导出他过去两周的 Apple Health 数据，统计白天心率、HRV 多久一个点，AirPods 有没有写心率。不用写代码 | 知道事件级心率能不能用、AirPods 值不值得算进来 |
| 1. 续航 | 手表 App 只录音、30 分钟一块传到 iPhone。两种做法各戴一整天：不开体能训练会话、开会话 | 从起床到睡觉不用中途充电（或只补一次），音频不缺块。同时看 Health 里平时心率点有多密、AirPods 有没有贡献 |
| 2. 转写 | iPhone → iCloud → Mac，FluentFlow Local 转写整天 | 一天的转写每句都有正确的绝对时间；抽查准确率 |
| 3. 两张表 | iPhone 导出 Health；Mac 切事件、写两张表 | 他看一天的事件列表，切分和标签基本对 |
| 4. 每天的记录 | 按「日记和 Glimmer」定下的那条路出每天的整理记录 | 连续一周每天自动出现，他觉得有用 |
| 5. 规律 | 攒满 4 周后每周报告 | 他认为至少有一条是他之前没意识到、事后核对也成立的 |

每一阶段都能单独用，第 1 阶段不过（续航不够）就停下重新评估，不往下做。

## 风险

- 续航：最大的未知，第 1 阶段专门测。
- 手表后台录音被系统中断（来电、Siri、内存紧张）：需要自动续录和缺块提示，待实测频率。
- 手表平时心率采样稀疏（静止时几分钟一次），短事件的心率可能只有一两个点；短于 10 分钟的事件不参与心率比较。
- 全天录音和夜里戴表测睡眠抢电：白天用掉太多，夜里可能撑不住，需要固定一个充电时段（如晚饭或洗澡时）。
- 手表在袖口、户外有风噪，转写可能出错或编出没说过的话；没人说话可能性高的片段宁可丢掉。
- 跨天规律需要几周数据才有意义，前一个月只有每天的记录、没有规律。

## 和 Gemini 方案的对照

两份一致的：手表只录音、心率事后读 Health；文件块和事件分两层；iCloud 中转到 Mac、faster-whisper 转写；事件表和日表放私人目录的 SQLite；先测续航再往下做；跨天比较要设样本门槛、回事件表解释。

采纳了它的：凌晨 4 点分日；心率采样数和来源、佩戴覆盖率、低可信日排除；白天 HRV 不算到事件上；日历和运动作为切事件的信号；工作日和休息日分开比、去掉极端一天再看；前两周只建基线；手表上的暂停和删除按钮；第 0 阶段先看已有 Health 数据；对照手写日记和身体数据；指出和 10-28 产品分工的冲突。

没采纳的：手表端按静音自动找切点（Mac 端整天拼起来转写，切口不影响，手表端越简单越省电）；音频转写后 24 小时就删（留几天供抽查）；声纹分离和别人原话脱敏进第一版（改为以后可加，本机准确度待测）；从对话里提取「我回头发你」这类承诺（超出这次要做的）；置换检验、错误发现率校正这类统计细节（到第 5 阶段实现时再定，结论只当候选已经兜住）。
